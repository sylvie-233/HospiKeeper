## 一、系统概述

### 1.1 定位

面向中小型民宿、小旅馆的**单机桌面软件**，聚焦「开房、退房、房态、登记、账单」核心业务闭环。不做线上 OTA、会员分销、多门店、财务 ERP。

### 1.2 形态与风格

- **桌面应用形态**：标题栏（最小化/最大化/关闭）+ 菜单栏（真下拉菜单）+ 左侧树形导航 + 内容区 + 底部状态栏，非网页后台布局；
- **控件风格**：参考 Ant Design 设计规范（主色 `#1677ff`、语义 Tag 色、紧凑 Table/Modal/Tabs、28px 紧凑控件高度）；
- **单机运行**：数据内置演示数据，正式版对应 MySQL 落库（见配套 SQL）。

### 1.3 角色与权限

| 能力 | 前台（FRONT） | 管理员（ADMIN） |
|------|:---:|:---:|
| 房态看板、入住登记、预定、退房结算、打扫 | ✔ | ✔ |
| 入住记录 / 退房账单 / 操作日志 | 仅看**自己经办**的 | 全部 |
| 房间管理、房型管理（含改价）、操作员账号 | ✘ | ✔ |
| 修改自己的密码 | ✔ | ✔ |

> 实现约定：管理员专属页面/按钮以 `admin-only` 标记隐藏；前台的数据列表在查询层按经办人过滤。

## 二、界面总体设计

### 2.1 登录窗口（启动页）

- 独立窗口「登录 - 云栖民宿管理系统」，账号 + 密码 + 登录按钮；
- 登录成功后按角色切换视图，状态栏与用户区显示「姓名（角色）」；
- 演示账号：`admin/123456`（老陈·管理员）、`front01/123456`（小王·前台）。
- 校验：账号不存在 / 密码错误 / 账号已停用，分别给出提示。

### 2.2 主窗口框架

| 区域 | 内容 |
|------|------|
| 标题栏 | 系统名 + 最小化/最大化/关闭 |
| 菜单栏 | 系统（退出登录/修改密码）、业务（看板/入住/预定/在住）、报表（经营统计）、帮助（关于）；下拉菜单项可直达对应页面 |
| 左侧导航 | 10 个功能页签，前台与管理员可见项不同；预定/在住带未处理数量角标 |
| 内容区 | 当前功能页，标题栏同步显示页面名 |
| 状态栏 | 当前登录人、实时时钟（30 秒刷新）、房态汇总摘要 |

### 2.3 导航结构

```
房态看板 ｜ 入住登记 ｜ 预定管理 ｜ 在住/退房结算 ｜ 入住/账单记录 ｜ 统计报表 ｜ 操作日志
＋ 管理员专属：房间管理 ｜ 房型管理 ｜ 操作员账号
```

## 三、功能模块详细设计

### 3.1 房态看板（首页核心）

- **房卡矩阵**：按楼层分组的房间卡片，卡片显示房号、房型、标价，颜色区分六种房态：
  空闲(绿) / 已入住(蓝) / 预定(紫) / 打扫中(青) / 维修(橙) / 停用(灰)，底部图例实时统计各态数量；
- **筛选**：楼层下拉、房型下拉（均由数据动态生成，非硬编码）；
- **卡片快捷操作**（点击房卡弹出快捷菜单，按当前房态给出可用动作）：

| 当前房态 | 可用动作 |
|----------|----------|
| 空闲 | 办理入住 / 新增预定 |
| 已入住 | 查看在住 / 追加消费 / 退房结算 |
| 预定 | 转入住 / 取消预定 |
| 打扫中 | 保洁完成（→空闲） |
| 维修 / 停用 | 恢复（→空闲） |

### 3.2 入住登记

- **表单**：客人姓名、手机号、身份证号、房间（仅列出空闲房）、入住时间（默认当前）、预计退房时间（默认**次日 12:00**）；
- **议价**：单价默认取房间标价，可手动修改，校验 `≥ 底价`，低于底价提示且不允许提交；
- **自动计算**：房费 = 单价 × 晚数；应收 = 房费 + 押金；
- **押金**：默认取房间押金标准，可修改；
- **同住人**：可动态添加多名同住人（姓名/手机/身份证）；
- **提交成功**：生成入住单（单号 `I+日期+序号`），房间 → 已入住，写「开房」日志。

**校验规则**：必填项缺失提示；手机号/身份证格式校验；预计退房时间必须晚于入住时间；房间必须处于空闲态。

### 3.3 预定管理

- **列表**：单号（`R+日期+序号`）、客人、电话、房间、到店时间、状态、备注、操作；
- **新增预定**：客人信息 + 预定房间（空闲房）+ 到店时间；成功后房间 → 预定；
- **转入住**：待到店预定一键转入住，自动带入客人信息与房间，退房时间默认**次日 12:00**（避免 0 晚无法结算）；
- **取消预定**：需二次确认，房间恢复空闲；
- **详情**：点击单号弹出预定详情对话框。

### 3.4 在住 / 退房结算

**在住列表**：房号、客人、入住时间、预计退房、单价、押金、已产生费用（仅金额，不含明细；明细在结算弹窗查看）、操作。

**追加消费**：在住期间随时录入杂费（如矿泉水 ¥4、泡面 ¥6：项目 + 金额），即时入账。

**退房结算弹窗**（核心流程）：

1. 顶部展示在住信息快照（房号、客人、入住/预计退房时间）；
2. **追加项明细**：列出该入住单全部消费记录及合计；
3. 录入：实际退房时间、损坏扣费、备注；
4. **实时试算**（结算公式）：

```
应收合计 = 房费 + 追加消费合计 + 损坏扣费
结算差额 = 应收合计 − 已收押金
  差额 > 0  → 应补收（红色提示）
  差额 < 0  → 应退款（绿色提示）
  差额 = 0  → 押金正好抵扣
```

5. 计费口径：按天计费（跨 12:00 算新一天）；支持**加钟**，加钟时按 `标价 ÷ 24 × 小时数` 向上取整；
6. 确认结算后：生成结算单（`S+日期+序号`）→ 入住单标记已退房 → 房间自动进入**打扫中** → 写「退房」日志。

### 3.5 入住 / 账单记录（同页 Tab）

- **Tab 1 入住记录**：全部历史入住单，列：单号、房号、客人、入住/退房时间、房费、状态（在住/已退房 Tag）、经办人；
- **Tab 2 退房账单**：全部结算单，列：单号、房号、客人、房费、追加、损坏、押金、结算差额、结算时间、经办人；
- **筛选**：房号、姓名、手机号、时间段；
- **详情**：点击单号打开**票据风格详情**（dl-* 版式：单据头部、明细行、合计区、经办落款），入住单与结算单样式统一；
- **权限**：前台只能看到自己经办的单据。

### 3.6 统计报表

面向「民宿管理员最想看什么」设计，四块布局：

1. **指标卡区（8 张）**：今日营收（含环比↑↓）、本月累计营收、当前入住率、平均房价、今日开房数、今日退房数、待到店预定数、待打扫房数、押金占用；
2. **近 7 日营收柱状图**：内置数据为近 30 天（周末峰值），取末尾 7 天渲染；
3. **时间段营收查询**：起止日期选择，支持近 7/30 日快捷按钮与**自定义区间**；结果含区间总营收、日均营收、环比上一同长度区间、逐日明细表 + 柱状图；
4. **房型经营分析表**：房型｜标价｜当前房态（各态数量）｜近期入住率（分母为可售房，排除停用/维修）。

### 3.7 操作日志

- 记录：时间、操作人（姓名（角色））、类型（开房/退房/预定/取消预定/打扫/改价/登录等）、对象、明细；
- 按类型筛选；前台仅见自己的日志，管理员见全部。

### 3.8 房间管理（管理员）

- 列表：房号、楼层、房型、床位、标价、底价、押金、带窗、独立卫浴、状态、操作；
- 新增/编辑：完整房间档案；校验房号唯一、标价 ≥ 底价；
- 删除：有在住/预定关联的房间**禁止删除**；
- 停用/维修：状态切换入口，停用房间不参与入住与入住率统计。

### 3.9 房型管理（管理员）

- 房型 CRUD：名称、基础定价、备注；名称唯一；
- **改名联动**：房型改名后同步刷新所有房间的冗余房型名（看板、筛选下拉、记录快照字段）；
- 改价写「改价」日志（如：基础定价 ¥188 → ¥198）。

### 3.10 操作员账号（管理员）

- 账号 CRUD：登录账号（唯一）、姓名、角色（前台/管理员）、状态；
- **约束**：不能停用当前登录账号；账号名重复提示；
- 启用/停用切换、修改密码（旧密码校验 + 两次新密码一致）。

## 四、核心业务流程

### 4.1 散客入住流程

```
看板点空房卡（或导航进入）→ 填写客人信息/选房/时间
  → 议价（≥底价）→ 确认押金 → 提交
  → 房态: 空闲→已入住 → 生成入住单 → 写日志 → 看板/角标刷新
```

### 4.2 预定 → 入住流程

```
新增预定 → 房态: 空闲→预定 → 客人到店 → 一键转入住（带入信息）
  → 房态: 预定→已入住 → 预定单标记已转入住（关联入住单号）
（客人未到：可取消预定 → 房态: 预定→空闲）
```

### 4.3 退房结算流程

```
在住列表/房卡 → 打开结算弹窗 → 显示追加消费明细
  → 录入退房时间/损坏扣费 → 实时试算（补收/退款）
  → 确认 → 生成结算单 → 入住单已退房 → 房态: 已入住→打扫中 → 写日志
```

### 4.4 房态生命周期

```
空闲 ──入住──> 已入住 ──退房──> 打扫中 ──保洁完成──> 空闲
  │               │
  └─预定──> 预定 ──┘（转入住）
        │
        └─取消──> 空闲
（任意时刻管理员可标记 维修 / 停用，完成后恢复空闲）
```

## 五、数据与单据规则

| 规则 | 说明 |
|------|------|
| 单号编码 | 入住单 `I+yyyyMMdd+3位序号`；结算单 `S+…`；预定单 `R+…` |
| 金额显示 | 统一 `¥xx` 格式，保留两位小数 |
| 操作人显示 | 统一「姓名（角色）」，如 `小王（前台）` |
| 数据自洽 | 演示数据保证：在住必有入住单、账单差额与结算公式一致、日志与实际动作对应 |
| 房间可售口径 | 入住率/房型分析的分母 = 总房数 − 停用 − 维修 |

## 六、桌面实现映射建议（Avalonia）

| 原型元素 | Avalonia 实现 |
|----------|---------------|
| 左侧导航 + 内容区 | `ListBox`/`TabControl`（或 `NavigationDrawer` 模式） |
| 菜单栏下拉 | `Menu` + `MenuItem` |
| 各列表页 | `DataGrid` + 顶部筛选栏（`ComboBox` 动态绑定） |
| 房态看板 | `ItemsControl` + 自定义房间卡片 `UserControl`，按楼层分组 |
| 弹窗（入住/结算/详情） | `Window` 或 `OverlayPopup`（Modal 风格） |
| 记录详情票据 | 固定版式 `UserControl`（可对接打印） |
| 指标卡 | `ItemsControl` 卡片列表 |
| 7 日营收柱状图 | `LiveCharts` / 自绘 `Canvas` |
| 房态颜色 | 语义色资源字典（与原型 `STATUS_COLOR` 一致） |
| 权限视图 | 角色驱动的导航可见性 + 查询层经办人过滤 |

## 七、范围边界

**v1 包含**：房态看板、散客入住（议价/同住人/加钟）、预定管理、追加消费、退房结算、记录与票据详情、统计报表、操作日志、房间/房型/账号管理、登录与角色权限、修改密码。

**v1 明确不做**：打印（单据打印留二期）、黑名单、钟点房独立定价、OTA 对接、小程序预订、会员储值、多门店、发票开具。
